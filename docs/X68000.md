# Sharp X68000 — experimental development

The X68000 prototype is progressing quickly, using the shared 68000 work from
Mega Drive and Neo Geo. It has produced local standalone games on Windows and
Debian, with guarded native execution of code loaded into RAM.

Current work includes DIM/XDF disks and M3U sets, shared controls and display
options, F8/F9 states, keyboard/gamepad autofire, and initial automatic disk
transitions. The defaults are W/X for buttons A/B. F1 and F2 open and close
their menus; Shift+F1 restarts at once, as on every console. More games, disk sequences, hardware cases and low-power Linux
performance still need qualification.

Nineteen game sets are converted on Windows and Debian with the current
machine runtime. Each native export matches a fresh reference run (CPU, memory,
picture, PCM and clock traces) on a 4,000-frame route plus mouse and keyboard
routes, and resumes identically after a saved state. No fallback was observed on
those sampled paths, and the campaign traces match between Windows and Debian. This does not establish complete gameplay coverage or exact hardware
fidelity. The seven existing console profiles retain their documented scope.

## Availability

The X68000 profile is included in the converter as an **experimental** profile.
Add DIM/XDF disks or an ordered M3U set, and select your own IPL ROM and font
ROM (CGROM) in **Options → Sharp X68000**. On the first conversion the converter
fetches hissorii/px68k, Geolith and GenesisRecomp at their pinned revisions,
like the other profiles' dependencies. No firmware, disk, generated game or
private instruction observation is distributed.

The machine runtime contains no file of the GPL-declared libretro fork. It is
built from hissorii/px68k (2014) under Kenjo's noncommercial terms, NONAKA
Kimihiro's BSD files and cisc's FMGEN terms, with Musashi (MIT) and
Retro-Recomp's own MIT host glue and snapshots. hissorii's port is used on the
same noncommercial terms as the rest of the Kenjo lineage, as PX68k has been
distributed since 2013 (permission requested publicly in
[hissorii/px68k#15](https://github.com/hissorii/px68k/issues/15), without an
answer). Notices: [machine runtime](../licenses/x68000-machine.md),
[FMGEN](../licenses/fmgen.md), [Musashi](../licenses/musashi.md).

What is measured, kept separate: native code (each export matches a fresh
reference run on bounded joystick, mouse and keyboard routes, with the fallback
interpreter count reported), CPU and hardware checks (authored video, audio,
timing, session and disk vectors and 20 CPU guards), and continuation after a
saved state. Complete gameplay, exact hardware fidelity and physical latency are
not established by these checks.

## Projects used by the prototype

- [PX68k by hissorii](https://github.com/hissorii/px68k), revision
  `74ddbb37b4e12b77362a4e12f28ceb5aaa593684`: machine devices from Kenjo's
  WinX68k/Keropi, NONAKA Kimihiro's xkeropi and hissorii's port, with cisc's
  FMGEN for the YM2151.
- [Geolith / libretro](https://github.com/libretro/geolith-libretro), revision
  `2dc88e3fa72ff404213a65d6eb5bb33baa687f73`: the Musashi CPU baseline reused
  with X68000 callbacks.
- [GenesisRecomp](https://github.com/mstan/segagenesisrecomp) and
  [m68k-recomp-core](https://github.com/mstan/m68k-recomp-core): shared 68000
  decoding and native instruction work.
- [PX68k / libretro](https://github.com/libretro/px68k-libretro) served as the
  earlier development reference; none of its files is compiled any more.

The application credits link to these repositories. Their individual terms
remain applicable; the RetroRecomp MIT notice does not relicense them.

## What comes next

Continue hardware and gameplay qualification, improve the machine-runtime
distribution boundary, and extend multi-disk coverage. More consoles and
classic computers are planned. Each new machine will have its own experimental
stage and validation before being described as supported; no release dates or
complete compatibility are promised.
